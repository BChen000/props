# BChen000/props

Reusable props for GJ's animated YouTube Shorts: the code, settings and styles behind past videos. New videos start from parts that already work and match each channel's look.
- Read this file first.
- Open a prop's README only for props you're going to use.
- Each README says what the prop made, how to run it, its gotchas and what it can't do.

## Working from this repo
1. **Find props:** pick the props for your channel from the index below.
2. **Set up once per session:** run `./setup.sh <channel>`. It installs the Python packages, downloads fonts, models and (for Wildlore) the asset pack, and checks Blender and ffmpeg. Use `--check` to only report.
   - Installs don't survive a long pause in a session, so rerun it after one.
3. **Build:** make the new video in its own work folder, importing props by path. If one video needs a prop changed, copy the prop there and keep the repo version general.
4. **Give back:** when the video is done, add any new reusable piece as a prop (skill: `add-props-to-repo`), then run `python update_index.py` and open a PR.

## Rules for props
- **Layout:** `<channel>/<prop-name>/`, lowercase with dashes. Each prop folder holds:
  - runnable code with a settings block at the top, holding the shipped values
  - `style.json`
  - `README.md`
  - `preview.png`
  - `assets/`, only if needed
- **README sections:** a summary, the preview image, `**Used in:**` (with what was verified), `## Files`, `## Reuse`, `## Gotchas`, `## What it can't do`, `## Dependencies (tested)`.
- **Never commit:**
  - finished videos
  - font files: ship a `get_fonts.py`
  - model weights: ship a downloader
  - photos of real people
  - files over 25 MB
  - third-party assets of unclear licence: document them and their sources in the README instead
  - third-party assets of clear licence: ship a downloader that pins a commit and checks SHA-256 (see `animal-docs/wildlore-blender-kit/get_assets.py`)
- **Paths and outputs:** paths are relative to the script (`HERE = os.path.dirname(os.path.abspath(__file__))`) with env overrides. Outputs go to `out/` or `build/`, which are gitignored.
- **Testing:** test every script from a fresh clone before pushing, and only claim what was actually verified.

## Git (Claude sessions)
1. Attach the repo with `add_repo`: push access to contribute, read access to use. Clone it with `git clone --depth 1`.
2. Branch as `add-<topic>`, commit, then push with `git -c push.negotiate=true push -u origin add-<topic>`.
3. Open the PR with REST, because `gh pr create` fails here (GraphQL is blocked):
   ```bash
   gh api repos/BChen000/props/pulls -f title='...' -f head='add-<topic>' -f base='main' -F body=@body.md
   ```
4. GJ merges. Merge yourself only when asked: `gh api -X PUT repos/BChen000/props/pulls/<n>/merge`.

## Speed notes
- **Rendering is the bottleneck** in cloud sessions, which have 2 CPU cores and no GPU. Blender EEVEE runs about 10–25 s a frame for a forest shot. To save time:
  - draft at half size (`RES=540x960`)
  - look at stills of the busiest frames before a full render
  - queue shots and render them one at a time
- **Long renders:** run them in the background and poll them in the same turn; background jobs stop a few minutes after a turn ends. Most Blender props skip finished frames, so a stopped render resumes. Tell GJ the expected time before starting.
- **Use a GPU when there is one:** if GJ's Mac is linked to the chat (Claude desktop app, + -> Add folder) or he runs Claude Code on it, render there; it's far faster than the cloud CPU.
- **Two Dragons stack:** `./setup.sh animal-docs --bpy` adds Blender 5.3 as a Python module. Animated dragon frames take 5–13 s each, and painted-backdrop compositing 0.2–1.7 s a frame.
- **Wildlore assets:** `./setup.sh animal-docs` downloads the HDRIs, textures and bee model into `/home/claude/assets` in a few seconds. That's 56 MB, fetched from their original GitHub repos and pinned and hash-checked by `animal-docs/wildlore-blender-kit/get_assets.py`. No asset pack from GJ is needed.
